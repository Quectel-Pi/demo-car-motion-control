# 麦轮小车使用手册

> 适用硬件：Quectel Pi M2 主控板 + 幻尔树莓派5扩展板 A 款（RasAdapter5A）+ 麦轮底盘。

## 1. 这套东西能做什么

用手机或电脑打开网页，就能控制小车四个轮子：任意方向平移、斜行、边走边转、漂移、单轮点检，以及一键跑演示动作。

| 能做 | 说明 |
| --- | --- |
| 任意方向平移 | 摇杆给多少方向就走多少方向，不做 45° 吸附 |
| 斜行 / 边走边转 | 平移与自转可同时下发 |
| 漂移 | 自转只加到后两轮 |
| 单轮点检 | 单独驱动任意一个轮子，用来查接线和转向 |
| 电池电压 | 页面实时显示，低于 6.9 V 标红 |
| 演示动作 | 预设动作一键运行（页面可选 7 套，见第 6 节） |

| 做不到 | 原因 |
| --- | --- |
| 看实际轮速 / 里程 | 扩展板没有编码器读取接口，页面的 mm/s 是**估算值** |
| 看姿态角 | IMU 只用于演示里的转角闭环，页面不显示姿态 |
| 灯光 / 蜂鸣器 / 舵机 | 当前版本未开放 |

## 2. 接线

扩展板直接插在主控板上，**不需要额外接线**（串口、地、电源都走 40pin）。

> 插拔 40pin 必须**断电**，并对准第 1 脚插到底；错位一位可能直接短路 5V/3.3V。

### 2.1 引脚

| M2 40pin | 作用 |
| --- | --- |
| Pin 8 | 串口发送，M2 → 扩展板 |
| Pin 10 | 串口接收，扩展板 → M2（电池电压） |
| Pin 9 | 共地 |
| Pin 2 / 4 | 扩展板向 M2 供电 |
| Pin 1 / 17 | 仅参考电平，不要用来供电 |

### 2.2 轮位

| 车体位置 | 插扩展板哪个口 |
| --- | --- |
| 左前 | **M1** |
| 右前 | **M2** |
| 右后 | **M4** |
| 左后 | **M3** |

接线按上表插好即可。**轮子转向不对不要反接电机线**，改 `config.json` 的方向配置。

### 2.3 供电

- 电池接扩展板，扩展板同时给电机和主控板供电；
- 桌面调试可以插 USB-C，但**不要与 40pin 的 5V 长期同时供电**；
- 电池电压低于 6.9 V 时页面标红、电机无力，属正常，先充电；
- 如果 Wi-Fi 搜不到、板子隔几分钟自动重启，优先怀疑**供电不足**而不是 Wi-Fi 设置：给主控板单独一路 5V/3A 以上的 USB-C 供电，扩展板只管电机。

## 3. 开机与启动

1. 断电状态下插好 40pin；
2. 把车架起来（轮子离地），手边留可随时断电的开关；
3. 开电池开关，等主控板启动完成；
4. 首次部署（只需一次）：

```bash
cd ~/projects/demo-car-motion-control
./install.sh      # 创建 .venv、安装依赖、体检系统缺哪些包
./run.sh          # 启动，终端会打印访问地址
```

`install.sh` 会检查系统依赖，缺包时打印可直接执行的安装命令：

| 包 | 用途 | 必须 |
| --- | --- | --- |
| `python3` | 运行程序 | **是** |
| `python3-venv` | 创建 `.venv` 隔离环境（缺了会退回系统 python3，也能跑） | 建议 |
| `curl` | 自检脚本 `preflight.sh`、`~/carurl` | 建议 |
| `iproute2` | `ip` / `ss` 命令 | 建议 |
| `network-manager`、`dnsmasq` | 让板子自己开热点（第 4.2 节） | 按需 |
| `rfkill`、`iw` | 无线排查 | 按需 |

> `run.sh` 会自己挑解释器：优先用 `.venv` 里的 Python，其次 `python3`。
> 如果提示 `Permission denied`（从 Windows 传来的仓库常见），改用 `bash run.sh`；
> 等价命令是 `python3 src/main.py`（缺少 pyserial 时程序会自动用内置串口实现）。

启动后终端会打印可访问地址，例如：

```Plain Text
  访问地址 : http://192.168.4.1:8080/
  深色主题 : http://192.168.4.1:8080/dark
```

地址以日志打印为准（IP 每次开机或 Wi-Fi 重连可能变化）。忘了 IP 时在板子上执行 `~/carurl`。

需要手动设开机自启：把单元里的运行用户和路径占位一起替换成本机用户名（模板用绝对路径，不写 `%h`——部分镜像在启动早期会把 `%h` 解析成 `/root`）：

```bash
# 把 User=CHANGE_ME 和路径里的 <user> 一起替换成实际用户名（如 welton）
sed -i "s|^User=.*|User=$USER|; s|<user>|$USER|g" scripts/demo-car-motion-control.service

sudo cp scripts/demo-car-motion-control.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now demo-car-motion-control
systemctl status demo-car-motion-control --no-pager
```

验证"上电自启"：`sudo reboot` 后等约 40 秒再连上来，执行

```bash
systemctl is-active demo-car-motion-control                                # active
ss -tln | grep 8080                                                       # 有 LISTEN
systemctl show -p ActiveEnterTimestamp --value demo-car-motion-control    # 接近开机时间
```

> 启动失败先看 `journalctl -u demo-car-motion-control -b --no-pager`：
> `status=217/USER` = `User=` 还是占位；`status=200/CHDIR` 且日志里路径是 `/root/...` = 单元里还在用 `%h`，改成 `/home/<user>/...` 绝对路径。

## 4. 连接与联网

### 4.1 页面入口

| 地址 | 说明 |
| --- | --- |
| `http://<板子IP>:8080/` | 默认页面，手机访问自动进精简版 |
| `http://<板子IP>:8080/dark` | 深色完整版 |
| `http://<板子IP>:8080/m.html` | 手机精简版 |

手机/电脑要和主控板在**同一个网络**里；服务不需要外网。

### 4.2 让主控板自己开热点

现场没有路由器时，让板子当热点，手机直连：

```bash
cd ~/projects/demo-car-motion-control
sudo ./scripts/setup_wifi_ap.sh                       # 默认热点
sudo SSID=QuectelPi-01 PASS=<至少8位密码> ./scripts/setup_wifi_ap.sh
```

| 项目 | 默认值 |
| --- | --- |
| 热点名称 | `QuectelPi`（可用 `SSID=` 改） |
| 热点密码 | 用 `PASS=` 指定（至少 8 位；不指定时脚本随机生成并打印） |
| 页面地址 | `http://192.168.4.1:8080/` |

- 一台无线网卡**同一时刻只能二选一**：自己发热点，或去连别人的 Wi-Fi；
- 切回连路由器：`nmcli connection up <连接名>`；再切回热点重跑上面的脚本；
- 手机连上提示「此网络无互联网连接」是正常的（热点只提供局域网），别让它自动切回移动数据。

## 5. 页面操作

| 操作 | 功能 |
| --- | --- |
| 拖动摇杆 | 任意方向平移，拖得越远越快（上限 80%） |
| 平移速度滑块 | 0~80% |
| 自转滑块 | ±60% |
| 漂移开关 | 后两轮反向加力 |
| 单轮点检滑块 | 单独驱动 M1~M4，查接线与转向 |
| 演示下拉 + Start | 运行演示动作 |
| Stop / 急停 | 四轮立即停转 |

键盘（桌面）：

| 按键 | 功能 |
| --- | --- |
| `W`/`A`/`S`/`D` 或方向键 | 四向与斜向平移 |
| `Q` / `E` | 左 / 右自转 |
| `空格` / `Esc` | 停车 |
| `Shift+Esc` | 急停 |

手机：长按 Stop 0.8 秒急停；切到后台会自动停一次车。

### 5.1 3D 视图说明

| 项目 | 说明 |
| --- | --- |
| 车头朝向 | **跟随真机 IMU 实测值**，和真车朝向一致（IMU 掉线或仿真模式下改为按指令估算） |
| 位置 | 按指令估算（无编码器），只用于"看起来在动"，不能当测量 |
| 镜头 | 默认固定机位、地面不动、车在场景里移动；控制台可用 `Car3D.setCameraMode('follow')` 切换跟随 |
| 朝向反了 | 控制台执行 `Car3D.setYawSign(-1)`（不改代码、刷新失效） |

## 6. 演示动作

页面选序列 → Start 即可；`Stop` 中止，`Pause`/`Resume` 暂停继续。演示在板子里跑，手机息屏或页面刷新不会中断。

| # | 名称（页面标题） | 参考时长 | 看点 |
| --- | --- | --- | --- |
| 1 | Full motion tour | 约 12 s | 一次看完八个方向和左右自转 |
| 2 | Star: out and back | 约 17 s | 八个方向出去再原路回中心 |
| 3 | 8-direction check | 约 10 s | 八个方向逐个点动，确认方向正确 |
| 4 | Drift showcase | 约 8 s | 后两轮加力形成漂移 |
| 5 | Single-wheel check | 约 8 s | 逐轮点动，标定接线用 |
| 6 | Square return (IMU closed loop) | 约 21 s | 走一个正方形回到起点，转角用陀螺仪闭环 |
| 7 | Distance check (300 mm) | 约 3 s | 直行固定时长，量距离做标定 |

首次使用建议顺序：先把车架起来跑 `Single-wheel check`（确认每个轮子都转、转向对），再跑 `8-direction check`（确认方向），最后落地跑其它演示。

## 7. 标定

小车没有编码器，距离与转角都是按时间估算的，所以距离会随电量和地面变化。

**标定直行距离**：

1. 跑一遍 `Distance check`，用卷尺量实际走了多少毫米（目标 300 mm）；
2. 打开 `config.json`，把 `board.max_speed_mm_s` 改成 `632 × 300 ÷ 实测值`；
3. 保存后重启服务即可，其他参数不用动。

**转角不准**：用 `Square return (IMU closed loop)` 做正方形；它靠陀螺仪控制转角，误差比按时间估算小很多。跑完发现整体走大了/走小了，调 `demo.home.scale`（走太远就调小）。

**转角闭环（IMU）调参**：一般不用动，出问题先按下面顺序看。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `demo.home.rot` | 20（%） | 粗转速度；越大越快也越容易打滑 |
| `imu.turn_kd` | 0.45 | 阻尼，越大刹车越早（冲过头就加大） |
| `imu.turn_tol_deg` / `settle_rate_dps` | 2.5° / 15 | 到位判据：角度到位**且**转速足够低 |
| `imu.turn_fine_deg` / `turn_fine_rot` | 6° / 12（%） | 进入精调的误差窗口与限幅 |
| `imu.turn_min_pulse` | 8（%） | 精调最小脉冲，低于此值推不动（车不动就加大） |
| `imu.heading_hold` | true | 直行航向保持（只对 0°/180° 生效） |

判定结果会写进日志：`arrived`（到位）、`give_up`（放弃精度但继续）、`timeout`（超时）。现场实测 4 次转角误差约 ±2°。

## 8. 安全

| 情况 | 车会怎样 |
| --- | --- |
| 点急停 | 立刻四轮停转并锁住状态 |
| 关掉页面 / 断网 | 8 秒没有指令，四轮自动归零（演示除外） |
| 串口线松动 | 页面提示链路异常，自动重连 |
| 手动停止服务 | 先让四轮停转再退出 |
| **服务进程被强杀** | 电机保持最后速度继续跑，**必须用电源开关断电** |

所以：现场一定留能随时断电的开关；调试和试动作先把车架起来，落地试车从 30% 以下速度开始。

## 9. 出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 页面显示「仿真（无硬件）」 | 串口没连上：检查 40pin 是否插到底、电池开关是否打开；板端执行 `python3 test_tools/serial_probe.py` |
| 页面打不开 | 确认手机和板子在同一网络；板端 `systemctl is-active demo-car-motion-control`、`ss -tln \| grep 8080` |
| 页面能开但按按钮没反应 | 板端执行 `curl http://127.0.0.1:8080/api/status`，看链路是否正常 |
| 轮子不转或只抖一下 | 电池电量低，或死区太大：调大 `config.json` 里 `board.deadzone_pct`（15 → 20~25） |
| 某个轮子转向相反 | 改 `config.json` 的 `board.motor_invert` 对应位，不要反接电机线 |
| 前进时车画圈 | 轮位插反了，按第 2.2 节核对 M1~M4 |
| 左平移跑到右边 / 原地左转变顺时针 | 改 `config.json` 的 `control.invert_angle` 与 `control.invert_rot` |
| 手机搜不到热点 | 看板子上 Wi-Fi 是否被杀掉：`rfkill list`；或改回独立 USB-C 供电（见 2.3） |
| 点按钮几十秒才响应 | 手机把请求走了移动数据：关掉手机「自动切换移动数据/智能网络切换」 |
| 电池电压标红 | 低于 6.9 V，充电 |
| 3D 车模不显示 | 浏览器不支持 WebGL；四轮数据和电压在下方卡片里照样能看 |
| 3D 里车头朝向和真车相反 | 控制台执行 `Car3D.setYawSign(-1)`；若整体正确但只有某一条边反，先确认 IMU 是否掉线 |
| 演示跑一半就停 | 看板端 `~/wheel-demo-events.log`：出现 `demo abort` 是 IMU 中途失效；出现 `start ignored` 是重复点按被拦下 |
| 转角总差 3~5° 补不上 | 静摩擦偏大：把 `imu.turn_min_pulse` 从 8 调到 12，或换平整地面重试 |

板端一分钟自检：

```bash
cd ~/projects/demo-car-motion-control
python3 test_tools/serial_probe.py     # 串口与电池帧（车不会动）
python3 test_tools/uart_loopback.py --watch   # 只看串口上有无帧（十六进制，只读）
./scripts/preflight.sh                 # 供电/串口/链路/网络/服务 只读检查
~/carurl                               # 打印当前可访问地址
```

若 `--watch` 收不到任何字节：先确认 40pin 插到底、板子已上电（板子每 ~200 ms 推一帧电池），
再确认波特率是 1 Mbps；怀疑 UART 本身有问题时，断电后用杜邦线短接 40pin 的 8/10 脚，跑
`python3 test_tools/uart_loopback.py`（不带 `--watch`）做回环自检。
